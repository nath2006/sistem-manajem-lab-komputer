# Bantuan sekolah: adaptasi ringan referensi GLPI

## Referensi yang benar-benar diperiksa

Inspeksi lokal tanggal 15 November 2026 (UTC+07), melalui sesi HTTP terautentikasi di `http://glpi.test`. Login browser sebelumnya timeout; jalur HTTP alternatif berhasil. Kredensial hanya dibaca dari lampiran permintaan dan disimpan dalam proses, tidak disalin ke repo/log. Tidak ada tiket, aset, konfigurasi, atau formulir GLPI yang disimpan/diubah; POST hanya untuk autentikasi. GET aplikasi dapat mencatat aktivitas login/view internal GLPI.

Halaman respons 200 yang diperiksa: `/front/central.php`, `/front/computer.php`, `/front/printer.php`, `/front/networkequipment.php`, `/front/ticket.php`, `/front/ticket.form.php`, dan detail tiket `/front/ticket.form.php?id=1`. Halaman menampilkan GLPI 12.0.2. Bukti teks lokal tersanitasi ada pada scratch `letris-ticketing/glpi-observed.jsonl`, bukan data contoh yang dibuat sendiri.

**Dipakai:** klasifikasi komputer/printer/perangkat jaringan, pemisahan Asset dan Bantuan, daftar tiket dengan status/prioritas/kategori/teknisi, dan kaitan item. Daftar pencarian tiket memperlihatkan dampak, urgensi, prioritas, kategori, teknisi, tipe item terkait, deskripsi tindak lanjut dan jumlah followup; detail memperlihatkan tab Item dan Riwayat. Konsep tersebut dipetakan ke aset bersama dan workflow tiket yang sudah tersedia di Letris.

**Dilewati:** struktur CMDB/relasi konfigurasi mendalam, kontrak/anggaran/lisensi, proyek, change/problem management lengkap, entitas bertingkat, aturan otomatis, SNMP/inventory discovery, plugin, OLA/escalation bertingkat dan katalog layanan berat. Sebagian nama ini terlihat sebagai menu/filter pada halaman yang diperiksa; modulnya tidak dibuka dan tidak diklaim sudah diuji. Isi form/timeline GLPI dimuat dinamis: inspeksi HTTP melihat shell/tab/filter, bukan bukti perilaku interaksi AJAX atau pengujian seluruh proses GLPI.

## Kontrak sebelum perubahan

- Shell `frontend/src/Layouts/Dashboard.jsx` menambahkan satu menu **Tiket Layanan** menuju `/ticketing` untuk semua role. Target tour memakai `data-tour-path="/ticketing"`.
- Route lazy `/ticketing` sudah berada dalam area terautentikasi `App.jsx`. Tidak perlu mengubah routing atau menambah `/bantuan`.
- Footer yang diperiksa hanya berisi copyright/versi. Pencarian shell/footer/fitur tidak menemukan modal kontak bantuan atau tombol help terpisah. Tidak ada fungsi kontak yang dihapus/diganti.
- `Ticketing.jsx`, form create/action/classification/SLA, list dan modal detail sudah menyediakan kategori, prioritas P1–P4 hasil matriks dampak/urgensi, status, assignment teknisi, komentar/riwayat, dan impor temuan. Backend memakai `service_tickets`, `ticket_events`, `ticket_sla_policies`; tidak dibuat tabel tiket baru.

## Perubahan yang diterapkan

1. Nama menu menjadi **Bantuan**; halaman menjadi **Bantuan · Tiket Layanan**. Href, target onboarding dan route `/ticketing` tetap sama, tanpa menu/path duplikat.
2. Opsi aset `GET /api/tickets/options` tetap bernama `devices` dan memakai `perangkat_id` bersama. Proyeksi kini mencakup `kategori`, `penggunaan`, `lokasi`, `nomor_inventaris`, serta nama aset/lab; tidak memuat harga atau sumber dana.
3. Dropdown **Aset IT (opsional)** menampilkan nomor inventaris, kategori, penggunaan, dan lab/lokasi, termasuk Printer dan Perangkat Jaringan Operasional tanpa lab. Nilai null tidak ditampilkan sebagai teks `null`; aset tetap opsional.
4. Baris tiket menyediakan tautan client-side **Lihat aset** menuju `/aset-it?asset={perangkat_id}` ketika memiliki kaitan aset. Query frontend ini memilih modal `AssetDetail` yang sudah ada pada route `/aset-it` terautentikasi dan membaca endpoint detail yang sudah ada `GET /api/assets/:id`; bukan route `/aset-it/:id` yang tidak terdaftar atau endpoint API baru. URL dapat dibuka ulang untuk memuat detail yang sama. Query kosong/tidak valid/duplikat tidak mengirim request detail; loading, error/404, muat ulang detail, dan tutup-ke-inventaris disediakan. Menutup modal hanya menghapus parameter `asset`, tidak membuang query lain. Tombol Detail dan tabel responsif yang ada tetap dipertahankan.

## Aturan yang tidak diubah

Role/scope baca dan tulis, status machine, assignment, pembentukan prioritas, snapshot/jam SLA 24×7 (pending tidak pause), verifikasi penutupan independen, reopen/cancel/escalation, optimistik version/409, transaksi, parent row locks, riwayat append-only, lifecycle aset, dan prasyarat perbaikan tiket impor tetap menggunakan implementasi sebelumnya. Membaca semua opsi aset bukan izin mengelola aset atau membaca semua tiket. Adaptasi ini bukan sertifikasi ISO/IEC 20000 maupun implementasi seluruh GLPI.
